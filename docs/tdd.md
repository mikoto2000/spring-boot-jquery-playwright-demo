# TDD 実行記録

2026-10-21 に実施。ユーザーから TDD の指定を受けた時点では Spring Boot 起動・API・DB の土台は作成済みでした。その後の画面開発を、先に受け入れテストを書き、失敗を観測してから実装する流れに切り替えました。これは Playwright を使った受け入れテストレベルの TDD です。

## 一覧・検索

- **Red**: `--grep '初期データ'` を実行。API のリセットは204で成功したが、画面の行は期待4行に対し0行。画面が未実装であることを確認。
- **Green**: jQuery で一覧、検索、カテゴリ、空表示、条件クリアを実装。同じテストが成功。
- コミット: `7b7e615`（テストと土台）、`58bcf2a`（一覧・検索）。

## 登録・入力検証

- **Red**: 登録ボタンが存在せず画面テストが失敗。API の不正入力テストも期待400に対し201で失敗。
- 調査: JSON の小数 `1.5` が Integer への変換で丸められていた。
- **Green**: 登録ダイアログと入力検証を実装。Jackson の `accept-float-as-int=false` で小数を拒否。未入力、不正数量、API 検証、保存失敗時の再送、HTML 入力のテストが成功。
- コミット: `eb32d40`。

- コミット: `9042221`。

## Refactor

- 保存・削除ダイアログに重複していた送信中制御を `setBusy()` に集約。入力とボタンの無効化、`aria-busy` の付与を共通化。
- リファクタリング後、Chromium 8件と WebKit 8件の成功を確認。
- Firefox 8件はブラウザの起動エラー。画面アサーションに達していないため、成功としては扱わない。詳細は README に記載。

## 実行環境の調整

最初に予定した18080番ポートは既存サービスが使用していたため、18765番に変更しました。既存サーバーを流用しない設定で、別アプリに対する誤ったテスト実行を防いでいます。

`git log --oneline --reverse` で、テスト定義 → 各機能の Green → リファクタリングの履歴を確認できます。

## ステップごとのスクリーンショット追加

- **Red**: 変更前の一覧テストを実行し、テスト結果を検査する一時レポーターで名前付きステップと PNG 添付を要求。機能テストは成功したが、ステップも画像も0件で検証が失敗。
- **Green**: `screenshotStep()` を追加し、既存の画面操作・検証を名前付きステップに整理。検証成功後に全ページを撮影して `step.attach()` で添付。
- **整理**: 撮影・添付を共通ヘルパーに集約。API のみを検証するステップは通常の `test.step()` を使用し、共通の初期一覧を除いて画像を付けない。
- **確認**: Chromium・WebKit の計16テストが成功。各画面ステップに PNG が1枚ずつ添付され、ファイルが PNG の形式であることを一時レポーターで確認（合計80枚）。HTML レポートのデモシナリオから編集フォームの添付画像を表示し、目視確認。
- 既存の Firefox 起動エラーは README 記載の環境制約として残り、今回の再検証対象は Chromium と WebKit。
